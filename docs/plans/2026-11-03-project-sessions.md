# 项目、多会话并行与发送后引导

用户确认：项目绑定工作目录，同项目会话共享目录，不增加跨会话文件互斥；全系统共享种群、技能、长期记忆和进化评分。每个会话独立 CEO、历史、图谱、队列和运行状态，并可同时执行。

## 架构决策

- 保留单 runtime 和共享 Registry/执行信号量；按 session 保留独立 CEO 实例，比每会话启动进程更轻且共享群体无需额外同步。
- 项目/会话目录使用 SQLite 元数据，不重命名既有会话文件；旧会话按历史任务的工作目录归组，无记录时使用默认目录。会话标题与文件 ID 分离。
- runner 按会话判忙；全局 busy 仅保留为管理员变更保护和旧接口汇总。执行 workspace/session 使用 ContextVar 并传递到线程池，避免全局 config._workspace 和事件归属串台。
- 前端显式携带当前会话 ID，过滤 SSE，加载请求防竞态，按会话保留布局；全局种群与参数不复制。
- 消息发送默认 queue。待处理卡片上的“引导”原位将该队列项提升为 interrupt，沿用已有批次边界引导机制，不重复提交。
- 左侧窄导航+项目会话树，中部当前会话，右侧可收起项目资料；默认浅色，保留已有主题选择。保留图谱/执行抽屉/全局种群入口。

## 实施与验收

1. 项目元数据 CRUD、会话创建/改名/归档与旧文件发现。
2. 运行上下文、独立 CEO、按会话启动/队列/状态/载入，线程池上下文传递。
3. 后端队列提升 endpoint，前端发送后“引导”与兼容提示。
4. 新布局、项目树及对话切换，保留原图谱和详情交互。
5. 测试两会话同时阻塞执行、各自继续/排队/引导、不同工作目录和事件不串台；目录持久化与输入验证；前端切换竞态和项目操作；浏览器真实交互及截图。
6. 不打断实际运行任务。后端新并行结构需重启加载，前端对旧后端显示能力提示。
