# 统一轮次与委派批次图谱实施计划

用户确认：CEO 和 worker 统一采用实例→输入轮次→委派批次→执行实例。轮次记录完整输入及本轮操作；批次记录各接收方和完整任务书。同一 execution_id 的上下文续接复用实例并增加其输入轮次；不同 execution_id 创建新实例。上级轮次不随子级返工增加。所有结构边仅导航关系，不再提供详情入口。

1. 保留执行状态归因 reducer，增加独立的交互投影：按 stage_id 合并并发批次、按 execution_id 区分实例、按输入事件建立轮次，维护重复派发到已有实例的附加连线。
2. 在后端事件中补全任务书、父/子执行标识及初始/续接输入事件；不改变实际调度和上下文续接行为。
3. web3 图谱展示投影节点，树布局保留首次归属，附加连接表达后续批次引用同一实例；删除边详情入口和虚拟锚点。
4. 修复轮次/序号详情组件的 React key 传参错误，展示全文及可展开操作/批次合同/汇报/复核。保留面板鼠标调宽。
5. 将投影快照随现有图谱保存，持久事件回放去重；旧图按已有任务记录迁移，缺失原文明确标注。
6. 回归覆盖并发2任务共用序号1、后续序号2、同上下文返工、新上下文新实例、递归 worker 委派、完整内容、历史保存恢复与重放幂等。运行单测、构建、隔离真实事件回放与浏览器交互验证。用户运行中任务不重启。

## 实施结果与验证

- 新增 graphFlow.ts，使用 execution_id 区分独立上下文；stage_id 合并并发任务；graph.instruction 明确区分新输入和续接。同一实例可以被多个批次引用，原始归属用于布局，附加连线保留各次派发关系。
- CEO/worker 的轮次节点展示完整输入和可展开操作；批次节点展示每份任务书、接收方、执行实例及派发/汇报/复核记录。修复旧 TaskDetail/GraphTooltip 误将 React key 当普通属性的问题。worker 轮次含 @ 的键也正确打开轮次详情。
- 后端保留原调度与 Hermes 续接行为，只补充全文合同、父/子执行标识、输入事件和 worker 派发波次元数据。A2A 初始子 execution_id 在派发时预分配，同一父输入下重叠的委派共享批次 ID。
- 交互快照随现有图谱存档；持久事件查询包含用户消息和 CEO 操作，回放按事件 ID 去重。旧图没有完整事件时迁移已有结构，并明确标注只有历史摘要。归档瞬态状态不再冒充实时运行。
- 浏览器隔离验证：一个 CEO 轮次中的并发两节点共用序号1，续接返工为序号2并复用原实例，新上下文为序号3新实例，worker 递归委派有自己的轮次/批次。点击轮次、批次、worker轮次均验证全文尾部可见及 CEO 操作可展开。
- 只读真实事件回放：a2a-live-test 41 个统一节点、2 条追加连线；mijia_lab 107 个统一节点、2 条追加连线。截图 web3/test/.unified-flow-*.png 与 .unified-real-*.png，复现脚本 web3/e2e/unified-flow.mjs；原 a2a-replay.mjs 已转到统一验收入口。
- 后端相关 58 项测试通过；曾额外运行 test_task_seq_reset，其中 test_exception_path_restores_done_and_next_round_resets 因原有 mark_interrupted 保留未完成状态而失败，未为本次图谱改动修改该行为。
- 实际 8021 服务仍 busy=true，未重启；前端 dist 已更新。新增后端全文/输入事件需运行任务结束后正常重启才能用于未来记录。旧事件未保存的原文无法补回。
最终验收：前端全量 176 项通过，后端相关 58 项通过，tsc/Vite 构建通过；产物 index-DUIHtRUl.js。新增回归还覆盖了旧存档并发批次迁移、同 task_id 不同 execution_id 的合同独立，以及状态事件先到时不重复建立初始轮次。
