# Web3 前后端状态一致性专项计划

**Goal:** 核对并修复 Web3 的内容、状态、颜色和连线动画，使它们与后端事件及当前快照一致。

**Architecture:** 后端执行记录、会话快照和带会话/执行标识的持久事件为事实来源。前端统一投影状态，颜色、文案和动画使用同一语义；断线与历史记录不冒充实时活动。保留 CEO → 轮次 → 批次 → 执行实例的现有交互结构。

**Tech Stack:** Python/Flask、持久事件总线、React/TypeScript、Canvas、Vitest、Playwright/Edge。

## 1. 审计与基线

- 追踪 `web_app.py`、`core/node.py`、`core/ceo.py`、执行记录和 Mesh 委派接口。
- 追踪 `web3/src/lib/{store,graph,graphFlow,graphCanvas,ceo}.ts` 与详情/概览/队列视图。
- 保存真实运行状态、会话文件校验与图谱投影的基线，列出状态语义对照和可复现问题。

## 2. 状态与身份

- 对照排队、启动、执行、等下属、验收、返工、完成、失败、阻塞、中断和未知状态。
- 精确使用 session / execution / task / delegation 标识，避免同一种群节点的不同实例串色。
- 为发现的问题先补失败测试，再修复投影、快照覆盖、乱序或恢复逻辑。

## 3. 颜色、文字与动画

- 图例、节点、详情、忙碌标签和概览统一语义；未知不能冒充成功或失败。
- 检查等待/排队节点及已结束会话是否仍有传输动画；区分任务执行、等下属与实际数据传输。
- 确保动效有后端事实依据，并验证浅深主题下相同状态的对应关系。

## 4. 场景验证

- 有针对性的 Vitest / 后端契约测试，包含迟到事件、相同节点的不同实例、SSE 重连和会话切换。
- 本地模拟执行完整生命周期并用浏览器检查颜色/动画/文案。
- 真实历史会话与真实任务逐项比对：任务仅在受控新工作区中进行，不修改旧研究成果，不改变 Worker 付费配置。

## 5. 验收与回滚

- 修复确认的问题，运行相关回归与完整前端检查，保存真实证据和仍存在的边界。
- Git 分阶段提交与备份；只有全部明确验收项完成才将 goal 标记完成，不声称绝对无 bug。
