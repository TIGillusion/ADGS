# 批次边界引导与普通排队实施计划

目标：保留现有在途工作，区分整任务结束后的 queue 与并发派发批次结束后的 interrupt 引导。

1. 消息入队增加 mode=queue|interrupt；默认 queue 兼容原接口。interrupt 只允许指向当前执行会话，避免跨会话注入。队列查看/编辑/撤销继续可用，并显示模式。
2. CEO 注册按会话消费引导队列的回调。在已派发任务全部返回后、下一次模型决策前，按顺序把引导作为真实用户输入加入原历史与任务事实，并保存；不重建 CEO 或工作实例。模型调用期间到达的引导在采用旧决策前补入，重新决策。
3. 一次 split_tasks 若包含多波依赖任务，发现引导待处理后停止派发新波次，等已提交 futures 全部返回；未派发任务完整交回 CEO。不中止任何现有子执行。
4. 普通排队仅在任务明确结束且不等待回答时自动接续；引导在结束交接窗口优先处理；异常、持久化失败保留消息。注入产生 chat.user 新轮次，保留执行实例身份。
5. web3 输入区可选择“排队”或“打断引导”，明确显示等待时机，队列行显示类型。补充 API、模式隔离、派发屏障、全文/持久化、批次后模型能读到引导、编辑撤销及前端交互测试。
6. 构建并在隔离测试服务验证 UI；不重启仍在执行任务的实际后端。

## 实施与验收

- web3 输入区新增“排队 / 打断引导”，队列行显示“任务后 / 本批后”，引导条目可编辑和撤销。空闲时直接按普通对话执行。
- API 默认保留普通队列行为；interrupt 返回明确模式回执并校验正在执行的会话。旧后端不返回模式时前端提示已按普通排队保存，避免误报引导已接入。
- CEO 在模型请求前后及完整派发工具结果写入后接收引导；不会把用户消息插进 assistant tool_call 与 tool response 中间。模型思考时到达的新引导会使尚未执行的旧决策失效。
- split_tasks 检测待处理引导后停止提交后续波次，等待已提交 futures 全部完成，将完整未派发任务定义作为 deferred 结果返回。已有执行及其上下文不取消、不重建。
- 引导原文与请求事实在原 CEO 会话内原子保存后才从队列确认移除；保存失败回滚内存且保留队列；跨会话引导拒绝。接入引导产生 chat.user，从而沿用统一图谱的新用户轮次规则。
- 普通队列在明确 task_done 且不等待用户回答时接续；交接末尾到达的同会话引导优先处理；异常保留待处理消息。
- 前端全量179项通过，类型检查与构建通过；后端批次引导/队列/runner恢复/CEO可靠性/执行可靠性/输入事件共114项（另5个subtests）通过。用事件同步验证两个在途任务完成后才返回，后续依赖任务未启动；验证下一次模型上下文中本批全部汇报紧邻引导原文。
- 浏览器隔离测试通过：模式与目标会话请求体、队列标识、修改及撤销。复现 web3/e2e/batch-guidance.mjs；截图 web3/test/.batch-guidance-queue.png。未向真实 CEO 注入测试消息。
