# Hermes 常驻会话实施计划

**Goal:** CEO 与 Worker 正常继续复用原进程、Agent 和上下文；只有进程丢失时恢复。完整消息提交、确认与轮次边界必须可靠。

**Architecture:** ADGS 管理每个执行/会话独立的常驻 Hermes 子进程。通过带消息 ID、长度及 SHA-256 的原子消息文件交接输入和回执，使用原生 Agent/CLI 多轮入口；终端仅作为输出观察通道。CEO 决策工具等待调度器返回真实结果，正常决策不再通过杀进程结束。

**Tech Stack:** Python、原安装 Hermes CLI/Agent、Windows Job Object、现有 SQLite 执行/终端记录、Web3 React。

## 已确认的现状

- `core/terminal_runtime.py` 每次启动 `chat --oneshot`，正常结束即清理进程树。
- `core/hermes_roles.py` CEO 工具写入决策后永久等待；父进程收到决策会终止该进程。
- `core/hermes_ceo.py` 每次决策重启 Hermes，正常情况下仅传递增量外部记录，但重复附带角色策略。
- `core/node.py` 普通续接、返工及终结确认均走 `_resume_hermes`。
- 安装版 Hermes 的 `HermesCLI` 保存 `agent` 与 `conversation_history`，原生多轮调用可保留这些对象。`--format stream-json` 仍为单次运行，不能误认为常驻双向协议。

## 约束

1. 不修改用户安装版 Hermes 源码；适配放在本仓库。
2. CEO 原付费模型与 Worker 原自建 Qwen 不变，不引入付费回退。
3. 同一执行正常继续不得偷偷创建新会话；压缩导致原生 session 迁移时跟踪真实 lineage。
4. 用户排队等 CEO 完全空闲；引导在本批全部下属汇报后交接，不截断正在执行的下属。
5. 子进程空闲等待输入不占工作并发名额、不计卡死超时；运行工具时沿用已有活动监测和父子槽位借还。
6. 输入全文原子提交，不模拟逐字键入，不以固定 sleep 判断内容是否输入完毕。接收确认与完成确认分开；同 ID 不重复执行。
7. 出错必须保留输入、回执、执行 ID、会话 ID 与具体原因。不得在未确认是否消费时自动重发导致重复执行。
8. 旧研究会话不启动、不改写；运行中不得直接重启服务。

## 实施顺序

- [ ] 在 `core/hermes_channel.py` 实现独立的消息/回执协议；测试半写文件不可见、中文多行超长文本完整、错误摘要拒收、同 ID 重试及并发提交。
- [ ] 在 `core/hermes_worker.py` 接入常驻入口，复用原生 Hermes 初始化与多轮历史；适配独立模块，保持旧恢复入口可用。验证连续三轮同 PID、同 Agent、同会话，以及日志仍连续可查。
- [ ] 在 `core/terminal_runtime.py` 引入按执行及会话归属管理的常驻进程生命周期；每一轮仍有独立 attempt、终端日志与数据库观察范围。区分本轮完成与进程退出。测试取消、退出、后台进程清理、同 profile 不同会话隔离、服务关闭回收。
- [ ] 修改 `core/hermes_roles.py` 与 `core/hermes_ceo.py`：CEO 工具回执后等待对应完整结果，不终止进程；下一次决策沿用原 Agent。覆盖真实工具结果、引导交接、结束后新消息及失败恢复，不重复追加整个角色策略。
- [ ] 修改 `core/node.py` 的普通继续入口：优先存活会话；退出后才加载持久历史。明确终结确认/返工属于新输入轮次，而不是新实例。原叶子、协调者与明确单工具约束必须随新合同更新。
- [ ] Web3/API 区分会话进程存活、本轮运行、等待下属、等待输入和恢复；空闲常驻不能显示“忙”或传输动画。保留历史终态和终端事件过滤。
- [ ] 真实新隔离会话验证：并行委派、原实例返工、长文本/中文/代码消息快速提交、排队转引导、重复请求、故障后恢复。逐轮记录 PID/Agent/session/消息摘要与消费次数；不凭模型自述认定保留上下文。
- [ ] 核对模型请求历史前缀、系统提示及工具定义稳定性；只有服务端提供缓存指标时才报告命中率变化。
- [ ] 相关回归、Web3 构建和真实浏览器检查通过后，空闲备份、部署、重开回放并提交 Git。

## 完成标准

正常多轮、返工和 CEO 工具交接实际保持原进程与 Agent；所有消息只在完整收到后消费且不重复。真正退出时恢复原会话，并明确显示恢复原因。排队、引导、并发、日志与图谱保持正确。全部实际发现的问题闭环后才将目标标记完成。
