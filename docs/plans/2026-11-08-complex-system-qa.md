# 完整复杂任务与 Web3 实测计划

**Goal:** 在全新工作区完成一个可独立验收的复杂任务，检查真实协作、调度与 Web3 的视觉交互；修复全部本轮可复现问题并复测。有限测试不能证明软件永无 bug，不以模型自述替代证据。

**Architecture:** 使用现有控制 API 启动真实 CEO/Hermes 与原自建 Qwen Worker。任务、执行记录、持久事件、真实工具调用和磁盘产物相互核对。Web3 使用真实 Edge 浏览器观察；外部验收脚本独立计算预期结果，不将答案交给实现节点。

**Tech Stack:** ADGS Python/Flask、Hermes/MCP、React/Canvas、Python 标准库、Playwright/Edge、pytest/Vitest。

## 任务设计

创建离线订单对账与审计工具：三份 CSV 包含正常、部分付款、超额付款、退款、重复 ID、未知订单、无效金额与 HTML 特殊字符。产出命令行处理器、独立 HTML 报告、集成测试和使用说明。固定 JSON 接口、金额规则和错误处理，外部验收逐项比对。

CEO 只了解项目、拆分委派、审阅与安排返工。派一名协调负责人；负责人并行委派计算模块与报告模块，之后委派独立集成测试。叶子禁止再分工。负责人派发后只协调，禁止自己执行项目代码或编写实现。普通执行报告可归档，但显式禁止报告落盘的只读复核不得额外写文件。

第一批运行中通过真实聊天界面发送排队消息、编辑、原位引导：增加报告筛选结果导出 CSV 的明确需求。要求沿用原负责人及相关执行上下文，测试新输入轮次、序号、返工和交付更新。再做一次明确禁止落盘的只读最终复核，补上上一轮未实际复测的场景。

## 检查与证据

1. 启动前：检查服务空闲、Git 干净、原会话内容与输入文件基线；保存备份和当前模型身份。新工作区仅含合成测试数据，不触碰旧研究文件。
2. 实际运行：对照执行树与 MCP 调用，确认并行和依赖；排队、等下属不被当作工作或卡死；完成子任务后负责人复核，CEO 承担决断与最终汇报。
3. Web3：浅/深主题、桌面/窄屏、聊天滚动、Markdown/长路径、项目搜索归档与忙标签、图谱节点/轮次/批次详情、拖动缩放、面板拉宽、终端和事件筛选。检查溢出、遮挡、焦点与关闭操作。
4. 状态：精确比对 session/execution 身份、颜色与文字；只在真实派发/汇报短时传输；返工保留旧结果；历史/断线无假活跃；模型故障必须有原因和可恢复状态。
5. 交接：真实引导仅在本批汇报后消费；观察明确失败/返工或需求变更的原实例续接。重连、切会话与整页刷新不丢内容或伪造时间。
6. 产物：外部重新计算每条订单、汇总与问题列表，验证输入 SHA-256；用浏览器检查产出报告的搜索、过滤、主题、转义和 CSV 导出；独立运行实现测试及额外边界数据。
7. 问题闭环：记录复现、原因、代码修复、先失败后通过的必要回归、部署与真实复测。运行中不重启服务；需要部署时先安全保存/暂停仅本测试会话，随后恢复原执行。
8. 结束：新任务完整交付且 CEO 正常收尾，队列为空、无遗留活跃实例；重启后回放；原会话数据保留。最终相关回归、证据、Git 提交与备份齐备。
