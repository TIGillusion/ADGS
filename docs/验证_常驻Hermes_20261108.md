## 真实发现并修复的平台问题

1. 长工具参数错误被误报为数组类型问题。明确 JSON 出错位置和未执行状态，并提供原生数组示例；Mesh 常用工具直接暴露 schema，减少双层 JSON。拒绝 `probe` 等无正式合同占位派发，不自动猜补用户任务内容。
2. Windows Job 取消后 ConPTY 再次 kill 产生 WinError 5。改为 Job 唯一终止进程树，终端负责排空和释放。
3. 通用输出文件描述误生成根目录验收要求。按明确实际路径验收，保持正式交付物和显式写入路径的严格校验。A 的旧失败记录保留，负责人读取实际产物后复核通过，没有复制多余文件伪装修复。
4. Git Bash 选中无扩展名 Linux `rg`。本机 Windows 适配优先同路径存在的 `rg.exe`；原生接口三种路径形式复测通过，不改安装版源码或远端执行规则。
5. 新终端 lifecycle 记录导致旧阅读器序号跳过及重连。Web3 正确消费新记录并区分轮次结束、进程仍待输入。
6. 原生 CEO 工具的 420 秒通用超时会早于实际派发结束，污染历史结果。仅 CEO 注册决策工具豁免该通用截止时间，仍保留调度层实际监督和原生中断检查；父进程要求明确的实际结果接收确认，拒绝把提前结束当成已交接。
7. 常驻入口遗漏无人值守标记，且角色钩子提前导入导致已有 `--yolo` 参数未及时生效。恢复原生初始化顺序、单次运行上下文和会话占用检查；两轮真实命令与 45 项相关回归通过，证据 `native-entry-latest.txt`。

旧 CEO 的超时历史没有改写。故障进程先备份再明确关闭，待真实下属结果返回后恢复原历史；普通叶子的补工未因这次修复重新启动。一次计划重载负责人的请求与自然结束竞态，实际保留了负责人原进程，不能把它记作成功重载。
