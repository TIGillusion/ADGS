# 设计:节点大脑的进化与管理层涌现

> 2026-10-22 设计思考,应用户「节点也能学会拆分任务、总结拆分经验,最终涌现总监/组长型管理节点,并有长期偏好的下属」之问。
> 本文只做设计,未改任何代码。所有机制均映射到现有代码的具体挂点。

## 一、现状盘点:我们离"管理进化"有多远

节点目前由两部分构成:

| 部件 | 现有实现 | 是否进化 |
|---|---|---|
| 手(执行) | hermes worker:技能固化(skill 基因)、记忆、会话经验 | ✅ 技能随繁殖重组遗传 |
| 脑(决策) | AGENT:`decide()` 决定 自己干/拆分委派/向上澄清,`evaluate()` 验收 | ❌ 每次决策从零开始,prompt 静态 |

关键观察:**管理行为的原始素材每天都在产生,只是被丢掉了**。每次 `split_tasks` 决策(怎么拆、拆几块、依赖结构)、每个子任务的结果(通过/返工/失败/超时)、每个委派对象的选择,都是一条管理经验——但 `AGENT.decide` 不记录、不复盘、不遗传。Node 的全部字段(describe/score/success_rate/tasks_done)都是**执行者维度**,没有管理维度。

同时系统里已存在一个事实上的管理者:CEO。它的 split_tasks 也没被沉淀——第一代管理经验无从继承。

## 二、设计总纲:不设职位,只造市场

核心原则:**管理层必须是涌现的,不是任命的**。系统不硬编码"总监/组长"标签,只提供四样东西:

1. **记录**(管理行为有账本)
2. **评分**(管理结果有独立于执行的度量)
3. **选择压力**(大任务优先流向善管理者)
4. **遗传**(管理经验可繁殖传递)

当某些节点在"把任务拆对、把人用对"上形成可度量的优势,路由自然把复杂任务导向它们 → 它们获得更多委派机会 → 形成稳定团队 → "总监"作为生态位涌现。职位是结果,不是设定。

## 三、四层机制

### 第 1 层:管理经验账本(Management Ledger)

**挂点**:`node.py::_work_inner` 的 split_tasks 分支与 `_delegate` 收尾处。

每次委派(无论成败)追加一条结构化记录(存 `agent_gene_db` 或新的 sqlite):

```json
{
  "manager": "ags_578",
  "task_signature": "<任务书 embedding 向量 + 任务类型关键词>",
  "plan": {"n_subtasks": 3, "granularity": "……", "dependency_shape": "chain|fan|dag", "subtask_goals": [...]},
  "assignments": [{"child": "ags_602", "trust_before": 0.6}],
  "outcome": {"passed": 2, "rework": 1, "failed": 0, "unjudged": 0,
               "wall_time": 812, "budget_ratio": 0.44, "rework_reasons": ["粒度过粗:两章并一章返工"]},
  "verdict": "good_split | too_coarse | too_fine | wrong_person | bad_scope"
}
```

`verdict` 由一次廉价的 AGENT 复盘调用生成(输入=计划 vs 结果,输出=五选一+一句话归因)。这是**大脑进化的最小单元:让每次决策产生一次带标签的自我复盘**。

### 第 2 层:管理分(manager_score,独立计分)

**挂点**:`core/registry.py::Node` 增加字段;`node.py::_evaluate_delegation` 扩展。

Node 新增:`delegations`、`delegation_pass_rate`、`rework_rate`、`avg_budget_ratio`、`manager_score`(由前四项合成,EWMA 更新)。与现有执行 score **并行不混合**——一个优秀的执行者不该因为不善管理被降执行分,反之亦然。

管理分的信号全部来自**子任务的客观验收结果**(passed/rework/unjudged),不来自管理者自我报告,防刷分。

`_evaluate_delegation` 已有雏形(子任务通过率→分数),缺的是**结构化归因**:区分"拆错了"(verdict: too_coarse)和"用人错了"(wrong_person)——前者扣管理分中的"规划"分量,后者扣"用人"分量。两个分量分开,才能涌现"善规划"与"善用人"两种管理风格。

### 第 3 层:经验回灌(大脑学会查自己的笔记)

**挂点**:`core/agent.py::decide()` 的 prompt 组装处(约 L288)。

decide 前用任务 embedding(复用 `utils/embedding.py`)在账本里检索 top-k 相似历史记录,注入 prompt:

```
【你的管理经验】(来自你过去 {n} 次委派)
- 类似任务「统计+报告」曾拆 3 块并行,全部一次通过;拆 5 块时出现 2 次返工(粒度过细)。
- ags_602 在「下载/部署」类子任务上 7 次委派 7 过;ags_567 同类任务返工率 60%。
- 上次教训:验收标准未写"数字必须可复算",导致 1 次返工。
```

这一步让 AGENT 从"每次从零决策"变成"带着自己的战绩决策"——**大脑的进化不是改权重,是长记忆**。检索的 playbook 同时限一份精简摘要进 Node(随 describe 一起被重组遗传,见第 4 层)。

### 第 4 层:信任边与团队(长期偏好下属)

**挂点**:新的边表(trust_edges: manager_id, child_id, trust, n_joint);`node.py::_delegate` 的子任务分配处。

- 每次委派结果更新 trust:passed +δ、rework −δ/2、failed −δ、unjudged 不动;trust ∈ [0,1] 初始 0.5。
- 委派分配时,候选(由 router 专精匹配产出)按 `0.7×专精匹配 + 0.3×trust` 排序——**既有"专业对口"的底线,又有"知人善任"的空间**。专精不足时即使信任高也不选(防任人唯亲)。
- trust ≥ 0.75 且共同委派 ≥ 5 次的 pair 视为**稳定配合**,UI 组织架构图上连线。
- **遗传**:evolution 繁殖时子代继承父母信任边的 50%(类似 `_skill_union` 做 `_trust_union`)——团队文化跨代传承;父母的管理 playbook 摘要同样并入子代。淘汰 manager 时其边自然冻结——组织随之重组,生态自然。

## 四、管理层的涌现判据(动态角色,非永久标签)

节点满足以下全部条件时,在路由与 UI 中呈现为 manager(纯计算属性,随时可失):

- `delegations ≥ 10` 且 `delegation_pass_rate ≥ 0.75`
- 委派占其总任务比 ≥ 40%(防"只管不做"——执行分低于阈值时路由不再给大任务)
- 存在 ≥ 2 条稳定配合信任边(有"自己的人")

层级自然形成:manager 的大任务可再委派给小 manager(现有 `max_delegation_depth` 机制),按其下游稳定团队规模与委派深度统计,**"组长"(1 层团队)与"总监"(含 manager 下属)是两个统计台阶,不需要新机制**。

路由改动(一处):`router.score_nodes` 对大任务(任务书含多个验收项/长时预估)给 manager 倾斜:`final = base × (1 + λ×manager_score)`;小任务不变,执行者生态不受冲击。

## 五、防退化设计(关键)

| 风险 | 对策 |
|---|---|
| 刷管理分(故意拆碎任务刷委派数) | 管理分信号=子任务验收,拆碎导致返工率升 → 扣分;委派占比过高且执行分低 → 路由不再倾斜 |
| 任人唯亲(只派给信任高的弱者) | 专精匹配权重(0.7)压过信任(0.3);子任务失败双向扣双方 |
| 经验僵化(老节点凭历史压制新品种) | 沿用现有 PUCT 探索项;playbook 注入带"过期惩罚"(记录 older than N 天降权) |
| 涌现假象(单轮运气) | 全部指标 EWMA + 最低样本数;掉出判据即摘角色 |
| CEO 榜样缺失 | 冷启动种子:把 CEO 历史 split_tasks 决策回灌账本作为"第一代管理经验" |

## 六、实施路线(每步独立可验证,可随时停)

- **Phase 1(纯记录,零风险)**:账本 + Node 管理字段 + verdict 复盘。跑一周攒数据,验证:记录覆盖率、复盘标签分布是否合理。
- **Phase 2(大脑起效)**:decide 注入 playbook 检索;`_evaluate_delegation` 分"规划/用人"两个分量。验证:同型任务的返工率对比(注入前后 A/B)。
- **Phase 3(选择压力)**:路由 manager 倾斜 + 信任边 + 委派偏好。验证:大任务是否自然流向少数节点;稳定 pair 是否出现。
- **Phase 4(遗传与层级)**:evolution 重组 playbook/信任边;组织架构图 UI(web3 新视图)。
- **观察指标**:管理分基尼系数(是否集中到少数节点=层级化)、稳定 pair 数量、大任务返工率趋势。

## 七、一句话总结

现有的进化只作用于"手"(技能),这套设计把同样的达尔文循环套到"脑"上:**决策留下账本,账本变成记忆,记忆参与评分,评分引导任务流向,流向塑造团队,团队写进基因**。总监与组长不靠任命——当拆分能力成为种群中最稀缺的可度量优势时,它们就是自然选择的结果。
