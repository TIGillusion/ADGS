## 修复结果

| 问题 | 依据与修复行为 |
| --- | --- |
| 高分节点也显示红色 | 列表、档案、图谱提示共用评分配色；缺失评分显示未知，不当作零分 |
| 概览把缺失评分算成零 | 均值仅计算实际有限数值，无数据不伪造评分 |
| 排队或等下属时连线永久流动 | 仅持久派发/汇报事件触发 3 秒流点，汇报逆向流动 |
| 历史、断线或闲置也暗示活动 | 历史、断线、过期事件不持续流动；等待实例与闲置 CEO 不持续执行呼吸动效 |
| 中断被当作执行失败 | 统一排队、执行、协调、验收、完成、未通过、中断、受阻、待验收、等待补充和未知状态 |
| 返工残留上次通过标记 | 同一执行续接时清除当前通过标记，增加输入轮次，保留旧批次结果 |
| 漏事件后实例长期残留旧状态 | `/api/state` 增加按会话隔离的精简执行快照，以 execution_id 和 node_id 精确确认 |
| 等下属与重获并发名额混用 | 运行时区分等待下属、等待并发名额和真正恢复；协调角色本身不冒充正在等下属 |
| 迟到请求覆盖新状态 | 拒绝旧请求回包与过时状态，保留与终态兼容的迟到验收评分和证据 |
| A2A 汇报没有进入聊天 | 实时派发/汇报进入聊天；会话隔离，完整协作内容保存在轮次/批次操作详情 |
| 合并模式进入独立验收后仍标为执行 | 三条验收路径统一先持久化 acceptance 并发布 evaluating，再调用验收模型 |
| 聊天顶部暂停、受阻和失败也显示绿点 | 与图谱实例共用语义和主题色；等下属显示协调色与静态状态点 |
| 重开会话伪造用户发送时间 | 从本会话持久用户事件恢复；缺失或重复输入对应不完整时显示“时间未记录” |
| 明确禁止报告文件却强制报告落盘 | 明确禁止创建报告/所有文件优先；普通只读任务仍保留系统报告归档，外部写路径不扩权 |

CEO、轮次、批次使用角色色；工作实例使用状态色。流点表示近期消息事件，不代表持续网络吞吐。未知记录不会自动变绿。
