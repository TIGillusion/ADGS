## 已修复的问题

| 问题 | 修复后的依据与行为 |
| --- | --- |
| 高分也显示红色 | 节点列表、档案和图谱提示直接使用同一评分配色；缺失评分显示未知，不当作零分 |
| 概览把缺失数据算为零 | 均值只计算实际有限数值，无数据不伪造评分 |
| 排队、等待下属时连线永久流动 | 流点仅由持久派发或汇报事件触发，3 秒后消失；汇报逆向流动 |
| 重开历史图谱或断线仍暗示传输 | 历史、断线和过期消息不持续流动；闲置 CEO 与等待节点不持续执行呼吸动效 |
| 中断误当任务失败 | 统一完成、未通过、中断、受阻、待验收、等待补充、排队、执行、协调与验收状态 |
| 返工残留上次通过状态 | 同一执行续接时清除当前通过标记，增加输入轮次，保留过去批次结果 |
| Worker 漏事件后长期残留旧状态 | `/api/state` 新增按会话隔离的精简执行快照；按 execution_id 与 node_id 精确确认 |
| 等下属、重新取得并发名额不区分 | 运行时发布等待、排队、恢复事件，详情依据真实等待标志显示；协调角色本身不冒充正在等待 |
| 迟到请求覆盖新状态 | 拒绝旧请求回包与过时状态覆盖，保留与终态兼容的迟到验收评分和证据 |
| A2A 汇报没有进聊天 | 委派与汇报内容进入聊天，保持会话隔离 |

CEO、轮次、批次使用角色色；工作实例使用状态色。图例与实际 Canvas 共用状态语义与主题变量。流点表示近期消息事件，不代表网络字节吞吐。
