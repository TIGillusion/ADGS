# ADGS 备份与回滚

备份放在 `D:\user_illusion\test\ADGS-backups`。这个目录与 ADGS 并列。代码由 Git 管理，会话、数据库、节点档案、模型凭据和研究产物单独备份。

## 代码回滚

- `git-store` 保存本地 Git 元数据，`adgs-code-baseline.bundle` 是可独立克隆的初始回滚点。
- 在 ADGS 目录运行 `git log --oneline` 查看提交。用 `git diff` 核对尚未提交的改动。
- 只恢复某个文件时，先用 `git show <提交>:<文件>` 核对版本，再运行 `git restore --source=<提交> -- <文件>`。
- 要验证整套代码，可以用 `git clone <bundle路径> <新目录>` 在新目录恢复。原工作目录里的 `.git` 文件即使丢失，外部 Git 元数据和 bundle 仍可用。

## 数据恢复

1. 打开备份根目录里的 `latest-snapshot.txt`，定位最近已校验的快照。用快照内的 `manifest.json` 核对范围。
2. 在独立目录验证恢复。快照内的 `runtime`、`data`、`config` 对应运行目录中的 `.adgs_runtime`、`data`、`config`。用同一快照里的 SQLite 文件成组恢复。
3. 从清单中的 `hermes_baseline` 复制节点档案基线，再把 `hermes-delta` 覆盖到新目录。按清单里的 `hermes_absent_from_current` 排除快照时已不存在的旧文件。
4. `research-artifacts` 是原研究工作区 `.adgs_artifacts` 的独立副本。先核对回合和交付清单，再把需要的文件恢复到项目。
5. 确认恢复结果后，在服务空闲并停止运行时替换正式文件。启动后检查会话、原执行 ID、终端记录和项目路径。
