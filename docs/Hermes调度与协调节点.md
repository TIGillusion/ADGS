# Hermes 调度与协调节点

CEO 使用 Hermes 做决策，固定为 CEO 职位。模型、地址和密钥继续通过 Web3 系统设置中的 CEO 配置调整；Worker 保留原有自建 Qwen 配置，不跟随 CEO 切换。

CEO 始终只协调，不亲自执行任务。可少量只读了解项目来制定计划；代码、计算、文件修改、运行验证和最终报告落盘交给 Worker。`single_task` 代表委派一个 Worker。固定人设维护在 `config/ceo/SOUL.md`，专用技能维护在 `skills/adgs-ceo/SKILL.md`；每次 CEO 启动自动同步，旧人设保存在 CEO profile 的 `backups/adgs-role`，恢复同一会话时也重新预载专用技能。

## 并发与等待

正式配置的执行并发上限为 5。所有 Worker 和嵌套下属共享同一个执行信号量。排队不会启动 Hermes，也不累计任务超时。父节点通过 `wait_delegation` 等待下属时归还执行名额，返回后重新排队取得名额；等待下属和重新取得名额均暂停无进展计时，仍支持用户取消。

正常任务取消总墙钟截止时间。系统根据实际收到的模型内容、工具完成记录、有效终端输出、工具子进程 CPU 和读写变化判断进展。重复心跳、等待标签和终端转圈不会单独证明任务有进展。真正的模型服务错误仍会保留执行记录并向上级汇报。

系统设置中的“模型请求预算”约束单次决策或验收请求；“无进展超时”用于正在执行的 Hermes。无进展判断不是程序正确性的证明，持续占用 CPU 的错误循环仍需上级检查或手动停止。

## 拆分后只协调

首次通过 A2A 派发下属后，当前 execution 持久化为协调者。Hermes 在工具执行入口读取角色标记，允许读取文件、查看节点、委派、等待及验收；拒绝终端和其他业务执行工具。同一个 execution 恢复后仍保留此角色。新的独立任务实例可以重新选择执行或拆分。

旧拆分记录在恢复时若缺少总体验收材料，也会追加下属任务完成补充，不再让父节点自己执行补工。协调者需要写最终文件时，应把写入任务委派给下属。

本机采用已安装的 Hermes 源码启动包装器安装角色钩子。冻结版 CLI 本身不包含该钩子；迁移运行环境时需要同时准备 Hermes 源码运行环境。

## CEO 会话与前端

CEO 工具通过 Hermes 原生工具定义提交决策，由已有 ADGS 调度器执行；任务账本、派发批次、用户排队和引导逻辑继续作为权威记录。每个聊天分别保存 Hermes session 和 execution ID，恢复原聊天时继续原上下文。

Web3 点击 CEO 可以查看 Hermes 执行面板。“执行事件”默认显示工具、阶段、协调决策和异常，隐藏会话流、心跳及原始终端行。“显示 Hermes 会话消息”可查看最近 100 条会话事件；完整终端日志仍可查看和下载。重要事件使用独立缓冲，避免被会话刷屏挤出。

聊天页的“CEO · Hermes”入口和图谱 CEO 根节点打开同一个固定 CEO 面板。聊天、图谱和详情共用 `chat.ceo_activity` 与 `/api/state.ceo` 的阶段数据，区分制定计划、只读了解、等待下属、审阅汇报、等待用户和中断恢复。一次 Hermes 决策进程结束不代表 CEO 的整个任务完成。活动事件不新增用户轮次、不生成 Worker 实例，也不作为普通聊天气泡刷屏。
